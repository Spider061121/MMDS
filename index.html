    • 二、数据结构的研究内容（1.1）
      • ① 计算机应用领域的转变
        • 早期：主要用于数值计算（科学计算）
        • 后来：处理扩大到非数值计算领域，能处理多种复杂的、具有一定结构关系的数据
      • ② 核心命题：程序 = 算法 + 数据结构
        • 由 N. 沃思（Niklaus Wirth）教授提出
        • 补充：1976 年图灵奖得主、Pascal 语言之父，著作《Algorithms + Data Structures = Programs》
      • ③ 研究内容（官方定义）
        • 研究非数值计算的程序设计问题中，计算机的操作对象以及它们之间的关系和操作
        • 通俗理解：对相关信息首先要考虑「如何表示、如何组织、如何存储」，进而设计出合适的数据结构及相应的算法
      • ④ 四个经典范例 —— 数据结构无处不在
        • 例1 书目自动检索系统 → 线性结构（线性表）
          • 书目卡片字段：登录号、书名、作者名、分类号、出版单位、出版时间、价格
          • 组织方式：书目文件 + 索引表
          • 索引表按书名 / 按作者名 / 按分类号分别建立
        • 例2 人机对弈问题 → 树形结构（树）
          • 把对弈过程展开成一棵博弈树，每一层对应一步走法
          • 机器需在树中搜索最优着法 → 引出搜索、剪枝、评价函数
        • 例3 文件系统的系统结构图 → 树形结构（树）
          • 根目录 /，其下 bin、lib、user、etc 等子目录逐层展开
          • 叶结点为具体文件，如 Stack.cpp、Queue.cpp、Tree.cpp
        • 例4 多叉路口交通灯管理 → 图形结构（图）
          • 顶点 = 一条通路（AB、AC、AD、BA、BC、BD…）
          • 连线 = 两条通路不能同时通行
          • 问题转化为图的着色：有连线的两个顶点不能同色
          • 最少颜色数 = 最少信号灯相位数（本题为 4 相）
      • ⑤ 课程的形成与发展
        • 形成阶段：60 年代初期相关内容散见于操作系统、编译原理、表处理语言；1968 年被列入美国一些大学计算机科学系的教学计划
        • 发展阶段：数据结构概念不断扩充，包括网络、集合代数论、关系等「离散数学结构」的内容
        • 我国：70 年代后期高校陆续开设该课程
    • 三、基本概念和术语（1.2）
      • ① 数据（Data）
        • 所有能输入到计算机中去的、描述客观事物的符号
        • 分类：数值性数据 / 非数值性数据（多媒体信息处理）
      • ② 数据元素（Data Element）
        • 数据的基本单位
        • 也称结点（node）或记录（record）
      • ③ 数据项（Data Item）
        • 有独立含义的数据最小单位
        • 也称域（field）
      • ④ 三者关系：数据 ⊃ 数据元素 ⊃ 数据项
        • 例：学生表 > 个人记录 > 学号、姓名……
      • ⑤ 数据对象（Data Object）
        • 相同特性数据元素的集合，是数据的一个子集
        • 例：整数数据对象 N = { 0, ±1, ±2, … }
        • 例：学生数据对象 = 学生记录的集合
      • ⑥ 数据结构（Data Structure）
        • 定义：相互之间存在一种或多种特定关系的数据元素的集合
        • 通俗：数据结构是带「结构」的数据元素的集合，「结构」就是指数据元素之间存在的关系
        • 三要素：逻辑结构 + 存储结构 + 数据的运算
      • ⑦ 层次一：逻辑结构
        • 含义：数据元素间抽象化的相互关系；与数据存储无关、独立于计算机，是从具体问题抽象出来的数学模型
        • 划分方法一（二分）
          • 线性结构：有且仅有一个开始结点和一个终端结点，且所有结点最多只有一个直接前驱和一个直接后继
          •   线性结构举例：线性表、栈、队列、串
          • 非线性结构：一个结点可能有多个直接前驱和直接后继
          •   非线性结构举例：树、图
        • 划分方法二（四分）
          • 集合：数据元素间除「同属于一个集合」外，无其它关系
          • 线性结构：一个对一个（1:1），如线性表、栈、队列
          • 树形结构：一个对多个（1:N），如树
          • 图形结构：多个对多个（M:N），如图
      • ⑧ 层次二：存储结构（物理结构）
        • 含义：数据元素及其关系在计算机存储器中的存储方式
        • 顺序存储结构
          • 借助元素在存储器中的相对位置来表示数据元素间的逻辑关系
          • 地址公式：Loc(aᵢ) = Lo + (i − 1) × m
          •   其中 Lo 为第一个元素的存储地址，m 为每个元素占用的存储单元数
          • 特点：随机存取、存储密度大；插入/删除需大量移动元素
        • 链式存储结构
          • 借助指示元素存储地址的指针来表示数据元素间的逻辑关系
          • 结点 = 数据域 + 指针域；头指针 h 指向首结点，尾结点指针为 ∧(NULL)
          • 特点：不要求连续存储空间、插入/删除方便；需额外指针空间、只能顺序存取
        • （教材补充）索引存储结构
          • 存储结点信息的同时附加索引表，索引项 = 关键字 + 地址
        • （教材补充）散列存储结构
          • 由结点的关键字直接计算出存储地址（哈希 /  Hash）
      • ⑨ 层次三：数据的运算
        • 对于一种数据结构，常见的运算有
        • 插入
        • 删除
        • 修改
        • 查找
        • 排序
        • 补充：还包括遍历、求长度、判空、置空等
      • ⑩ 三要素之间的关系（重要结论）
        • 逻辑结构唯一；存储结构不唯一；运算的实现依赖于存储结构
        • 逻辑结构和存储结构都相同，但运算不同，则数据结构不同
        •   典型例子：栈与队列（逻辑、存储相同，插入/删除位置不同）
        • 组合示意：线性结构 / 非线性结构 × 顺序存储 / 链式存储
        •   线性表、栈、队列、串、数组；树形结构、图形结构
      • ⑪ 数据类型（Data Type）
        • 定义：在一种程序设计语言中，变量所具有的数据种类
        • 严格定义：一组性质相同的值的集合，以及定义于这个集合上的一组运算的总称
        • 例：FORTRAN 语言 —— 整型、实型、复数型
        • 例：C 语言 —— 基本数据类型 char / int / float / double / void
        • 例：C 语言 —— 构造数据类型 数组、结构体、共用体、文件
        • （教材补充）分类：原子类型、结构类型、抽象数据类型
    • 四、抽象数据类型的表示与实现（1.3）
      • ① 抽象数据类型 ADT 的定义
        • ADT = Abstract Data Type
        • 一个数学模型以及定义在该模型上的一组操作
        • 由用户定义，用以表示应用问题的数据模型
        • 由基本的数据类型组成，并包括一组相关的操作
        • 是更高层次的数据抽象
      • ② ADT 与数据类型的区别
        • 数据类型：面向「值的集合 + 运算」，与具体语言相关
        • ADT：强调「抽象」，只关心逻辑特性与可执行的操作，不关心如何实现
      • ③ 三元组表示法：ADT = ( D , S , P )
        • D —— 数据对象
        • S —— D 上的关系集
        • P —— D 上的操作集
      • ④ ADT 的常用定义格式
        • ADT 抽象数据类型名 {
        •     数据对象：<数据对象的定义>
        •     数据关系：<数据关系的定义>
        •     基本操作：<基本操作的定义>
        • } ADT 抽象数据类型名
        • 基本操作的书写要素：操作名(参数表) + 初始条件 + 操作结果
      • ⑤ ADT 的意义：抽象与封装
        • 信息隐蔽 + 数据封装
        • 使用与实现相分离
        • 对外只提供接口（用户界面），隐藏内部物理实现
        • 例：线性表 ADT 对外暴露 查找 / 插入 / 删除 / 修改 等接口
      • ⑥ 表示与实现的基本思路
        • ADT 可以通过固有数据类型（整型、实型、字符型等）来表示和实现
        • 类似 C 语言中的结构（struct）类型，但增加了相关的操作
        • 教材中使用「类 C 语言」（介于伪码和 C 语言之间）作为描述工具
        • 上机时必须用具体语言实现，如 C 或 C++ 等
      • ⑦ 类 C 语言的约定要点（PPT 逐条）
        • (1) 预定义常量及类型（函数结果状态代码）
          • #define OK 1
          • #define ERROR 0
          • #define OVERFLOW -2
          • typedef int Status;  // Status 为函数返回值类型，其值是函数结果状态代码
        • (2) 数据元素约定为 ElemType 类型，用户根据具体情况自行定义该数据类型
        • (3) 算法描述为函数形式
          • 函数类型 函数名(函数参数表) {
          •     语句序列；
          • }
        • (4) 内存的动态分配与释放：使用 new 和 delete
          • 分配空间：指针变量 = new 数据类型;
          • 释放空间：delete 指针变量;
        • (5) 赋值语句　(6) 选择语句　(7) 循环语句
        • (8) 结束语句
          • 函数结束语句：return
          • 循环结束语句：break
          • 异常结束语句：exit(异常代码)
        • (9) 输入输出语句
          • 输入：cin（或 scanf( )）
          • 输出：cout（或 printf( )）
        • (10) 扩展函数
          • 求最大值：max
          • 求最小值：min
      • ⑧ （教材拓展）ADT 的实现机制
        • C 语言实现：用 struct 定义数据 + 一组函数作为操作
        •   如 List 结构 + InitList / ListInsert / GetElem 等函数
        • C++ 实现：用 class 把数据成员与成员函数封装在一起，天然支持封装
        • 关键：接口不变的前提下，实现可自由替换
    • 五、算法与算法分析（1.4）
      • 5.1 算法的定义与描述
        • 定义：一个有穷的指令集，这些指令为解决某一特定任务规定了一个运算序列
        • 算法的描述方式（4 种）
          • 自然语言 —— 易理解，但易产生歧义
          • 流程图 —— 直观形象
          • 程序设计语言 —— 可直接执行，但依赖具体语言
          • 伪码 / 类 C 语言 —— 教材采用，介于自然语言与程序语言之间
        • （补充）算法与程序的区别
          • 算法必须有穷；程序可以不满足有穷性（如操作系统是无限循环）
          • 算法可用自然语言、流程图、伪码描述；程序必须用编程语言书写
      • 5.2 算法的五个特性
        • 有穷性 —— 算法应在执行有穷步之后结束
        • 确定性 —— 每步定义都是确切、无歧义的
        • 可行性（有效性）—— 每一条运算应足够基本
        • 输入 —— 有 0 个或多个输入
        • 输出 —— 有一个或多个输出（处理结果）
        • 记忆口诀：有穷 · 确定 · 可行 · 输入 · 输出
      • 5.3 算法设计的四条要求（评价标准）
        • 正确性 —— 对合法输入能产生满足规格说明的结果
        •   层次：无语法错 → 对典型输入得正确结果 → 对边界/刁钻输入也得正确结果 → 对一切合法输入都得正确结果
        • 可读性 —— 便于阅读、理解与交流（好算法首先应易于理解）
        • 健壮性 —— 输入非法数据时能适当反应或处理，不会产生莫名其妙的结果
        • 高效性 —— 时间代价与空间代价（效率高、存储需求低）
      • 5.4 算法效率的度量方法
        • 方法一：事后统计法
          • 做法：利用计算机内的计时功能，用一组或多组相同的统计数据区分不同算法
          • 缺点①：必须先运行依据算法编制的程序
          • 缺点②：所得时间统计量依赖于硬件、软件等环境因素，掩盖算法本身的优劣
        • 方法二：事前分析估算法（本课程采用）
          • 一个高级语言程序在计算机上运行所消耗的时间取决于
          •   ① 依据的算法选用何种策略
          •   ② 问题的规模
          •   ③ 程序语言
          •   ④ 编译程序产生机器代码的质量
          •   ⑤ 机器执行指令的速度
          • 结论：同一算法用不同语言、不同编译程序、在不同计算机上运行，效率均不同 → 用绝对时间单位衡量算法效率不合适
          • 做法：去掉与软硬件有关的因素，只考虑「算法本身 + 问题规模」，以基本语句重复执行的次数作为时间量度
      • 5.5 时间复杂度 T(n) = O( f(n) )
        • 核心定义
          • 算法中基本语句重复执行的次数是问题规模 n 的某个函数 f(n)，算法的时间量度记作 T(n) = O( f(n) )
          • 基本语句：算法中重复执行次数与算法执行时间成正比的语句，对算法运行时间的贡献最大
        • 问题规模 n 的含义（随问题不同而变化）
          • 排序：n 为记录数
          • 矩阵：n 为矩阵的阶数
          • 多项式：n 为多项式的项数
          • 集合：n 为元素个数
          • 树：n 为树的结点个数
          • 图：n 为图的顶点数或边数
        • 渐进表示法（大 O 记号）的数学定义
          • 若 T(n) 和 f(n) 是定义在正整数集合上的两个函数，则 T(n) = O(f(n)) 表示存在正的常数 C 和 n₀，使得当 n ≥ n₀ 时都满足 0 ≤ T(n) ≤ C·f(n)
          • 含义：随着 n 的增大，算法执行时间的增长率与 f(n) 的增长率相同，称为渐近时间复杂度
        • 语句频度（Frequency Count）
          • 定义：语句重复执行的次数
          • 例：n×n 阶矩阵加法 c[i][j] = a[i][j] + b[i][j] 的频度为 n×n
          •   → T(n) = O(n²)，即矩阵加法的运算量与问题规模 n 的平方是同一个量级
        • 分析时间复杂度的基本方法（三步法）
          • ① 找出语句频度最大的那条语句作为基本语句
          • ② 计算基本语句的频度，得到问题规模 n 的某个函数 f(n)
          • ③ 取其数量级，用符号「O」表示
          • 总原则：时间复杂度是由嵌套最深层语句的频度决定的
        • 定理 1.1（多项式取阶）
          • 若 f(n) = aₘnᵐ + aₘ₋₁nᵐ⁻¹ + … + a₁n + a₀ 是 m 次多项式，则 T(n) = O(nᵐ)
          • 即：忽略所有低次幂项和最高次幂的系数，体现出增长率的含义
        • 常见渐进时间复杂度按数量级递增（由低到高）
          • O(1) 常数阶
          • O(log n) 对数阶
          • O(n) 线性阶
          • O(n log n) 线性对数阶
          • O(n²) 平方阶
          • O(n³) 立方阶
          • …… O(nᵏ) k 次方阶（多项式阶）
          • O(2ⁿ) 指数阶
          • O(n!) 阶乘阶
          • 重要结论：当 n 取得很大时，指数时间算法和多项式时间算法在所需时间上非常悬殊
        • 典型例题（PPT 例1 ~ 例4）
          • 例1　N×N 矩阵相乘
            • for(i=1;i<=n;i++) for(j=1;j<=n;j++){ c[i][j]=0; for(k=1;k<=n;k++) c[i][j]+=a[i][k]*b[k][j]; }
            • 基本操作语句为 c[i][j] = c[i][j] + a[i][k] * b[k][j]
            • 三层循环，频度 n³ → T(n) = O(n³)
          • 例2　三层递增循环
            • for(i=1;i<=n;i++) for(j=1;j<=i;j++) for(k=1;k<=j;k++) x=x+1;
            • 语句频度 = ΣᵢΣⱼ j = n(n+1)(n+2)/6
            • → f(n) 为 3 次多项式，由定理 1.1 得 T(n) = O(n³)
          • 例3　倍增循环（对数阶）
            • i=1;  while(i<=n)  i=i*2;
            • 设循环体执行 f(n) 次，则 2^f(n) ≤ n，即 f(n) ≤ log₂n
            • 取最大值 f(n) = log₂n → T(n) = O(log₂n)
          • 例4　顺序查找（最好 / 最坏 / 平均）
            • for(i=0;i<n;i++) if(a[i]==e) return i+1;  return 0;
            • 有的情况下，算法中基本操作重复执行的次数还随问题的输入数据集不同而不同
            • 最好情况：1 次（第一个元素即命中）
            • 最坏情况：n 次（最后一个元素命中或查找不成功）
            • 平均情况：平均查找长度 (n+1)/2 → 平均时间复杂度为 O(n)
        • （教材补充）最好、最坏与平均时间复杂度
          • 最好时间复杂度：最理想输入下的时间复杂度
          • 最坏时间复杂度：最坏输入下的时间复杂度，给出运行时间的上界保证
          • 平均时间复杂度：Σ(每种输入出现的概率 × 该输入下的执行次数)
          • 实际分析中通常关注最坏情况，因为它给出了确定的性能上界
        • （补充）复杂度增长曲线直观对比
          • O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)
          • n 增大时各曲线差距迅速拉大：n=1000 时 O(n log n) 尚可接受，O(2ⁿ) 已完全不可行
          • 工程意义：算法设计的努力方向是把指数级降为多项式级，再尽量降低多项式次数
      • 5.6 空间复杂度 S(n) = O( f(n) )
        • 定义：算法所需存储空间的度量，记作 S(n) = O( f(n) )，其中 n 为问题的规模（或大小）
        • 渐进空间复杂度
        • 算法要占据的空间分为两部分
          • ① 算法本身要占据的空间：输入 / 输出、指令、常数、变量等
          • ② 算法要使用的辅助空间 —— 通常重点关注的部分
        • 例5　将一维数组 a 中的 n 个数逆序存放到原数组中
          • 算法1（原地交换法）：for(i=0;i<n/2;i++){ t=a[i]; a[i]=a[n-i-1]; a[n-i-1]=t; }
          •   只借助一个辅助变量 t → S(n) = O(1)，称为「原地工作」
          • 算法2（辅助数组法）：for(i=0;i<n;i++) b[i]=a[n-i-1]; 再 for(i=0;i<n;i++) a[i]=b[i];
          •   需要 n 个元素的辅助数组 b → S(n) = O(n)
          • 结论：同一问题可用不同算法解决，时间 / 空间开销不同，需根据实际需求权衡
          •   即「以时间换空间」或「以空间换时间」

      • ① 本章小结（PPT 四条）
        • 1. 数据、数据元素、数据项、数据结构等基本概念
        • 2. 对数据结构的两个层次的理解：逻辑结构、存储结构
        • 3. 抽象数据类型的表示方法
        • 4. 算法、算法的时间复杂度及其分析的简易方法
      • ② 核心知识主线（一条线索串起全章）
        • 数据 → 数据元素 / 数据项 → 数据结构 → 逻辑结构 + 存储结构 + 运算 → ADT（抽象与封装）→ 算法 → 时间复杂度 / 空间复杂度
        • 一句话总结：数据结构研究「数据如何组织」，算法研究「数据如何加工」，二者用「效率」这把尺子统一衡量
      • ③ 易错点辨析
        • 数据结构 ≠ 存储结构；逻辑结构唯一，存储结构不唯一
        • 数据元素（结点/记录）≠ 数据项（域）：数据项是数据元素的组成部分
        • 数据对象是数据的子集，且强调元素「性质相同」
        • 算法 ≠ 程序：算法必须有穷性，程序可以没有
        • 判断线性 / 非线性看的是前驱与后继的个数，而不是数据值本身
        • 时间复杂度不是「执行时间」，而是执行时间的增长率；O(1) 不等于「只执行一次」
        • 基本语句是嵌套最深层的语句，不是循环语句本身
